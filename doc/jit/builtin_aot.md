# AOT-compiled builtin methods

The methods defined in Ruby in the top-level `*.rb` files (`numeric.rb`,
`kernel.rb`, `array.rb`, `pathname_builtin.rb`, ...) are compiled to C at
build time, from the same `insns.def` the interpreter is generated from.
When no JIT is enabled, calls to them run the compiled code instead of
interpreting their ISEQs. `RUBY_AOT=0` turns it off.

## Pieces

| file | what |
|---|---|
| `tool/mk_builtin_aot.rb` | the compiler; writes `builtin_aot.inc` |
| `builtin_aot.c` | runtime support, included into `vm.c` after `vm_insnhelper.c` |
| `vm_mini.c` | the VM for miniruby, without compiled code |
| `insns.def` (`leave`) | resumes compiled code a call returns into |
| `iseq.c` (`rb_iseq_each_descendant`) | the ISEQ walk both sides agree on |
| `builtin.c` (`rb_aot_attach`) | attaches compiled code to ISEQs as features load |

## Build

`builtin_aot.inc` is generated by miniruby, the same process that writes
`builtin_binary.rbbin`, from the ISEQs `RubyVM.each_builtin` yields. The
ISEQs ruby loads are byte-for-byte the ones that were compiled. miniruby
can't contain code it generates itself, so it links `vm_mini.o` (`vm.c`
without `builtin_aot.inc`), and ruby links `vm.o` (`VMOBJ` in `common.mk`).

For each feature the generator walks its ISEQ tree with
`rb_iseq_each_descendant` (exposed to it as `RubyVM.builtin_aot_iseqs`, in
miniruby only) and emits a table of `{iseq_size, function}`.
`load_with_builtin_functions` walks the loaded tree the same way and sets
`aot_func` on each ISEQ body. A size mismatch is a `rb_bug`.

Only method and block ISEQs are compiled. Class bodies, `rescue`/`ensure`
and top-level ISEQs run once or are entered from the exception handler.
Of those, the generator only compiles ISEQs where removing dispatch pays for
the cost of entering compiled code and of resuming it after each call into
Ruby. That cost is about as much as dispatching a few instructions. So it
compiles ISEQs with at least 20 instructions, or with a loop that runs at
least 6 instructions per call into Ruby. `Integer#times` qualifies (10 per
`yield`); `Kernel#loop` (3) and one-line wrappers like `Array#first` don't.
That is 57 of the 543 builtin ISEQs: `Integer#times`, most of
`pathname_builtin.rb`, the reporting code in `yjit.rb`/`zjit.rb`, and the
loops `array.rb`/`numeric.rb` define only when a JIT is enabled
(`with_jit`). Those last ones are dead code here, since compiled code is
never used with a JIT.

When there is no builtin binary (cross builds), the generated file is empty.

## Code

Each ISEQ becomes one C function. For each instruction the function contains
what `vm.inc` runs for it (`_insn_entry.erb`), minus the dispatch:

* `pc` is set to the constant next position, and `lindex_t`/`rb_num_t`/
  `OFFSET` operands are constants; the other operands are read from the
  loaded `iseq_encoded`;
* the operand stack and locals are the VM stack and `ep`, through the
  interpreter's own macros, so the frame is always what the interpreter
  would have at that point.

The interpreter's control-flow macros are rewritten per site:

| in `insns.def` | compiled |
|---|---|
| `JUMP(dst)` | after the instruction's trailer, `goto` the target label |
| `JIT_EXEC(ec, val)` in send-ish instructions | `AOT_EXEC_PUSHED`: if a Ruby frame was pushed, mark it and suspend (below) |
| `RESTORE_REGS(); NEXT_INSN();` | `return Qundef`: the interpreter continues |
| `CALL_SIMPLE_METHOD()` | an inline `opt_send_without_block` on the same call data |
| `INSN_LABEL(x)` | made unique per instruction |
| `leave`, `opt_invokebuiltin_delegate_leave` | pop the frame and return the value |
| `throw` | exit to the interpreter at that instruction |

Methods with optional parameters are entered at the `opt_table` position the
frame starts at.

## Calls into Ruby code: suspend and resume

Compiled code runs as `jit_entry` code does (`JIT_EXEC`, `jit_exec`), as the
last option, so it's never used while YJIT or ZJIT is on. When it calls
something that pushes a Ruby frame (`yield`, or a method defined in Ruby), it
does not nest `vm_exec`. That costs a `setjmp` per call; it's why C
`Array#each` is ~20% slower per iteration than `Integer#times` in Ruby.
Instead:

1. It sets `VM_FRAME_FLAG_AOT_RESUME` on the callee's frame. If the callee
   has compiled code, it calls that directly. Otherwise it returns `Qundef`
   and the interpreter runs the callee in the same `vm_exec` loop.
2. When `leave` pops a frame with that flag, it pushes the result as usual
   and calls the caller's `aot_func` with `resume` set. That jumps to the label after the
   call (a `switch` on `cfp->pc`).
3. Resumed code always returns control to the interpreter: at its own `leave`
   it stops right before the instruction and lets the interpreter run it,
   which handles `FINISH` and returning into further compiled frames.

No C frame is live while a call is suspended. So `break`, `next`,
`return`, `throw`, exceptions, Fibers and thread switches only ever deal with
VM frames. When an exception is caught by the compiled method's own catch
table, the interpreter runs the rest of that call from its bytecode.

Compiled code fires no TracePoint events. It returns to the interpreter on
entry, on resume, and after any instruction that can run Ruby, once
`ruby_vm_event_enabled_global_flags` is set (which then stays set).

## Assumption: builtin methods aren't redefined

Builtin code may assume that methods of builtin classes are the builtin
definitions. Box guarantees it: user redefinitions live in the user's box,
and builtins run in the root box. The interpreter checks for redefinition
with `BASIC_OP_UNREDEFINED_P` inside the `vm_opt_*` helpers. The compiled
code uses its own copies of those helpers, extracted from `vm_insnhelper.c`
by the generator (`aot_vm_opt_plus`, `aot_opt_equality`,
`aot_vm_case_dispatch`, ...), with that check defined as true. So
`Integer#times` keeps using the builtin `<` and `succ` after a user prepends
to or redefines them, while the user's own calls see the redefinition
(`test/ruby/test_builtin_aot.rb`).

## Measurements

Same binary, `RUBY_AOT=0` vs default, no JIT, x86-64, `ips`:

| | interpreted | compiled | |
|---|---|---|---|
| `1000.times {}` | 86.7k i/s | 96.9k i/s | +12% |
| `Pathname#cleanpath` | 697k | 756k | +8.5% |
| `Pathname#relative_path_from` | 211k | 228k | +8% |
| `Pathname#+` | 1.26M | 1.28M | +1% |
| `Kernel#loop`, `Array#first(2)`, `Float(x)`, `tap` | | | not compiled; within noise |
| `fib(30)`, C methods yielding (`upto`, `Array#each`) | | | within noise |

The last row covers the check every call into a Ruby method makes for
compiled code. `aot_func` sits next to `iseq_encoded` so that check reads a
cache line the call has already loaded. Before it was moved there,
`fib(30)` was 5-10% slower with compiled code enabled.

## Size

`vm.o` text is 0.77MB larger than `vm_mini.o` (1.07MB vs 0.30MB).

## Not done

* `throw` (3 sites) always exits to the interpreter.
* Calls from compiled code to C methods still go through the call cache and
  push a frame. With the assumption above they could be resolved when the
  feature loads, and called directly.
* After an exception is caught inside a compiled method, the rest of that
  call is interpreted (`jit_exception` isn't used).
* `win32/Makefile.sub` doesn't have the `vm_mini`/`VMOBJ` split yet.
* Moving `aot_func` shifted `rb_iseq_constant_body`; the two offsets ZJIT
  hard-codes in `zjit/src/cruby_bindings.inc.rs` were updated by hand, not
  by rerunning bindgen.
